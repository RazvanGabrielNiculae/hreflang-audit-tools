# Contributing

Contributions should improve the practical usefulness, reproducibility, or clarity of this project.

## Before opening a pull request

1. Keep examples synthetic or clearly sourced; do not commit credentials, private data, or proprietary datasets.
2. Separate observed facts from interpretation and preserve scope, dates, markets, languages, and denominators where relevant.
3. Run the repository's documented validation and test commands.
4. Keep links contextual. Do not add link exchanges, keyword-stuffed anchors, duplicate-content distribution, or links whose only purpose is backlink creation.
5. Prefer small changes with an explicit problem statement and evidence showing the change works.

A contribution must pass the repository QA workflow before it is ready to merge.
